# Bridge failure playbook

Use this file when a bridge command fails. Add every novel failure before retrying.

## Required incident record

Record:

- command and exact stage;
- durable status (`not-submitted`, `unknown-after-submit`, `timeout-after-submit`, `not-recovered`);
- whether content may already have been sent;
- safe next action and forbidden action;
- narrow cause and code fix;
- regression test and full-suite result.

Never infer submission from a visible window. Never infer non-submission after a post-submit websocket loss.

## Known failures and prevention

| Symptom / stage | Meaning | Safe response | Preventive rule |
| --- | --- | --- | --- |
| Global bridge silently selects a project-private or stale worktree runtime | The public wrapper retained a legacy project environment variable and ancestor lookup. A task launched inside an old worktree therefore connected successfully but exposed an obsolete schema, making the global Skill appear coupled to that project. | Treat as pre-submit; do not downgrade the payload, send through the selected project runtime, or infer compatibility from `discover`/`probe` alone. | Bundle the runtime in the bridge repository, install it to `%USERPROFILE%\.codex\bridge-runtime\dispatch-chatgpt-bridge`, and resolve only explicit `-Root` → `CODEX_BRIDGE_ROOT` → installed standalone runtime → repository-local runtime. Ignore legacy project variables and never walk ancestor directories. Regression: `standalone-runtime-tests.mjs` verifies runtime bundling, legacy-root rejection and dual Skill/runtime installation. |
| Standalone bootstrap fails to load `Get-AppxPackage` under PowerShell 7 with `Operation is not supported on this platform` | The Windows `Appx` module is available to Windows PowerShell 5.1 but cannot be loaded in the current PowerShell Core host. The bridge state was not created and no content was sent. | Keep the result pre-submit; do not restart Codex or fall back to a project startup script. | `start-chatgpt-bridge.ps1` must relay its exact bounded parameters to `powershell.exe` whenever `PSEdition` is not `Desktop`, then preserve the child exit code. Regression: the standalone bootstrap test invokes the self-test through both `powershell.exe` and `pwsh.exe` and requires the effective host edition to be `Desktop`. |
| Host clipboard read/write fails while a remote-control clipboard proxy owns it (`UURemoteClipboard`) | The remote-control client kept a hidden clipboard window open, so native `Clipboard.SetText` failed and every application appeared unable to copy or paste; this is host transport state, not a bridge composer or GPT route failure. | Do not send prompts through the visible UI and do not resend a job. Verify the exact owner class/process, then restart only the remote-control client if the user accepts a brief disconnect; keep its service running. | Re-test native clipboard round-trip after restart, confirm the owner window is gone, and keep bridge payloads file-based JSON so generation does not depend on host clipboard health. |
| `Runtime.evaluate` timeout during quick-chat open | Native open RPC may wait on renderer lifecycle; making the inner JS promise nonblocking is insufficient if CDP still uses `awaitPromise: true`. | If no `submittedAt`, diagnose and retry only under the original authorization. | Dispatch the lifecycle expression with CDP `awaitPromise: false`; verify the selected renderer and exact route independently. |
| Prewarm renderer reused or rebuilt unexpectedly | Electron may reuse the prewarm target or replace it with one new app page. | Stop before send when target identity is ambiguous. | Select only the exact prewarm target or one uniquely attributable rebuilt app target; never close user windows. |
| Attachment acknowledgement timeout | Upload succeeded but filename-only detection missed the visible attachment card. | Stop before send; do not assume references were attached. | Accept only visible attachment evidence from filename, accessible label, title or alt text; verify every local SHA before upload. |
| `CDP websocket closed` after `submittedAt` | Prompt may have been sent and generation may still finish. | Mark `unknown-after-submit`; seal the job and use read-only resume. | Persist conversation ID, marker and `submittedAt` before collection; never resend automatically. |
| `unknown-after-submit` with `main ChatGPT conversation navigation for <job> timed out` on embedded Quick chat | The current client rendered Quick chat inside the retained main renderer instead of exposing an attributable `/json/list` conversation target. The send click was recorded, but after submission the marker left the visible dialog and the synthetic local conversation ID could not be verified from the unchanged main URL. A live test also found the marker in Codex's own main-thread text, which is not target ChatGPT evidence. | Seal the job as `unknown-after-submit`; do not infer submission or generation from a global `document.body` marker, do not resend, and do not close the retained conversation. | Treat embedded Quick chat as a distinct runtime surface: scope all composer/snapshot checks to the visible `[data-pip-obstacle="quick-chat"]` dialog and require a read-only marker/history proof inside that root after submission. If the client provides neither an attributable target nor readable history proof, stop and report the exact ambiguity. |
| `main ChatGPT` fresh preparation records a synthetic ID while the visible embedded Quick chat has no conversation route | The retained `app://-/index.html` renderer is not itself a conversation target, but the Quick chat composer ancestor exposes the actual local identity through `data-above-composer-conversation-id="chatgpt:local-chatgpt:<uuid>"`. Keeping the pre-open synthetic ID makes post-submit attribution and recovery unverifiable even when the dialog is the correct one. | Treat any already-submitted job as sealed; do not rewrite its ledger identity or resend. For a new authorized job, stop before send if the exact DOM identity cannot be read. | Prefer the visible `[data-pip-obstacle="quick-chat"]` dialog for all main-surface gates and capture/validate its exact `local-chatgpt:<uuid>` identity after blank readiness. Store that identity in `prepared` and submission records. Regression: `embedded Quick chat uses its visible DOM conversation identity and snapshot root`; targeted bridge tests and the full suite must pass before a new send. |
| `main ChatGPT` active thread identity is ignored because it is `local:<uuid>` rather than `local-chatgpt:<uuid>` | The full integrated surface exposes the active Codex thread through `data-above-composer-conversation-id` or `[data-app-action-sidebar-thread-id]`; the bridge only looked inside a Quick chat dialog and only accepted native Quick chat IDs, so it fell back to a synthetic identity. | Keep already-submitted jobs sealed. For a new job, stop before send unless the active thread identity is exact and stable. | On `surface: "chatgpt-main-chat"`, resolve and validate `local:<uuid>` from the active composer/sidebar thread, use document-scoped rendered units only after identity equality, and keep native Quick chat validation separate. Regression: main identity expression test, live read-only identity probe, targeted bridge tests and full suite. |
| `renderer-ready-handshake: Runtime.evaluate` times out | Renderer-ready can wait on the same native window state as open; an inner detached promise still hangs when CDP itself awaits it. | No send during resume; preserve the original job. | Dispatch renderer-ready with CDP `awaitPromise: false`, then verify route/composer separately; cover detached evaluation parameters with a regression test. |
| `not-submitted` with `native quick-chat expected conversation route timed out` immediately after detached lifecycle dispatch | CDP returned before the asynchronous module import actually invoked native `open`; closing the controlling renderer too early prevented a reliable route transition. | Treat as pre-submit; the original authorization may be retried after a tested fix. | Store an ephemeral per-conversation lifecycle state in the controlling renderer, wait for `state=dispatched`, then release it and enforce the exact target route. Apply the same two-stage acknowledgement to renderer-ready. |
| `not-submitted` with `Multiple ChatGPT quick-chat renderers were found` | Stale quick-chat windows from earlier failed attempts were mixed with the renderer created or reused by the current prewarm. | Do not choose an arbitrary renderer and do not close user windows. | Snapshot target IDs before prewarm. Accept the unique newly appearing quick-chat target; if none appears, reuse only one pre-existing prewarm route. Keep later exact target/route gates unchanged. |
| `not-submitted` with `composer readiness ... timed out` after prompt insertion | The ChatGPT composer or send control exists, but the bridge matched one obsolete locale-specific `aria-label`; Lexical editors, `role="textbox"`, textareas, ProseMirror editors without a textbox role, `data-testid="send-button"`, or a different UI locale were falsely treated as absent. | Treat as pre-submit only when `submittedAt` is null and no lifecycle entry exists. Do not click an unproven control. | Every send-capable path, including `approve`, must share a bounded visible semantic selector set. Support Lexical, textbox, localized ChatGPT `aria-label`, ProseMirror and textarea composers plus stable test IDs and localized send labels; verify the exact marker or approval text before clicking. Cover focus, readiness and click expressions with regression tests. |
| Bare or staged `CDP websocket open failed` before submission | Electron replaced, temporarily suspended, or had not finished activating a renderer between `/json/list` selection and WebSocket connection. A target can remain listed yet reject WebSocket connections for tens of seconds before becoming connectable. | If `submittedAt` is null and the lifecycle ledger has no entry, keep the job pre-submit. Never connect to an arbitrary surviving page and never permanently discard a task-owned target after two fast failures. | Annotate every control/conversation session-open stage. Before each connection, refresh `/json/list` and accept only the exact conversation route, the owned prewarm target, or one uniquely attributable rebuilt target. Retry only WebSocket open failure/timeout under one overall deadline; cool a failing target down temporarily so a replacement can win, then re-probe it if it remains the only attributable renderer. Include target ID in the durable error. Fail closed on ambiguity or any later CDP error. |
| Repeated `quick-chat-conversation-session-open` failure while an older marker-owned quick-chat window remains open | The bridge attempted to connect the new renderer before dispatching the native `rendererReady` acknowledgement. The new prewarm target required that acknowledgement before becoming a stable conversation renderer, creating a handshake deadlock that was easier to reproduce when another bridge-owned window consumed capacity. | Preserve the older ambiguous conversation and ledger; do not delete, resend or close it merely to make the retry pass. Treat the new run as pre-submit when its report has no `submittedAt`. | Keep the controlling renderer alive while investigating this historical handshake failure, but do not make `rendererReady` a fresh-job prerequisite without runtime proof. |
| `quick-chat-conversation-session-open: No attributable CDP target became connectable` after open/renderer-ready dispatch attempts | The fresh path over-composed version-pinned `prewarm`, detached `open`, manual `rendererReady` and target-attribution heuristics. After restoring awaited `quickChatWindow.open` as the sole native gate, the same failure was reproduced with `open` completed but no new exact target remaining in `/json/list`; an older quick-chat target was present but could not be attributed to the new conversation. | Treat the job as pre-submit when `submittedAt` is null, preserve the sealed ambiguous conversation, and do not reuse the stale target. A separately authorized fresh run may use the visible main ChatGPT fallback only after its blank-surface gates pass. | Use awaited `quickChatWindow.open`, verify its returned identity, refresh `/json/list`, and connect only to the exact conversation route. If no exact target remains, use only visible `聊天` → `新聊天` → blank composer → zero visible units → no stop control on the retained main renderer; otherwise fail closed. Keep prewarm/renderer-ready helpers out of the production fresh path. Regression: bridge tests cover awaited open ordering, absence of production prewarm/renderer-ready calls, and the visible main fallback gates. |
| `main ChatGPT new conversation control timed out` on current clients | The fallback only recognized the legacy localized `聊天` entry. Current official clients can expose the same ChatGPT surface as a visible `Quick chat` control; when that control is missed, the dialog never opens and the subsequent `新聊天` gate times out. A visible drawer may also already represent a fresh conversation with a header rather than a clickable `新聊天` button. | Treat as pre-submit; do not click history rows or close the ChatGPT drawer. | Recognize visible localized `聊天`/`Quick chat` entries, scope gates to the visible `[role="dialog"]`, accept an exact visible `新聊天` header as already-new, and require only dialog-local composer, zero conversation units, and no stop control before submission. |
| `probe: The verified renderer does not expose the integrated ChatGPT chat entry` while the visible main renderer is already in ChatGPT mode | The probe only recognized the launcher labels `聊天`/`Quick chat`; the current official client can hide that launcher while showing a visible `当前模式：ChatGPT` mode control and the main ChatGPT composer. This was a probe false negative, not evidence that the CDP renderer is unavailable. | Keep the operation read-only; do not treat probe failure as permission to restart Codex or send. | Accept a visible `当前模式：ChatGPT`/`current mode: ChatGPT` control plus the visible composer as an active main-surface probe. Let main fallback use document-scoped blank gates in that mode, but require an exact DOM conversation identity before send. Regression: bridge probe and main-fallback tests; targeted bridge tests and full suite must pass. |
| `timeout-after-submit` on main ChatGPT while the dialog already contains the generated image | Collection used the global app snapshot: Codex's own visible `停止` button kept `hasStopButton=true` even though the ChatGPT dialog had no stop control and contained a `生成图像` blob image. | Keep the submitted job sealed and recover read-only; never resend. | Scope marker, assistant units, generated images, composer busy, stop and send controls to the visible ChatGPT dialog. A main-surface resume manifest carries `surface: "chatgpt-main-chat"` and attaches to the retained main renderer without opening or closing a conversation. |
| `main ChatGPT submitted marker timed out` after a prior submitted main-surface batch | The ChatGPT drawer may be collapsed after batch cleanup even though the main renderer remains valid; `/json/list` therefore has no separate target and the submitted marker is not in the visible DOM until the drawer is reopened. | Keep the submitted job sealed; do not fall back to a new chat or resend. | In read-only main-surface recovery, reopen only the visible `聊天` drawer when no dialog is present, then require the exact marker in the dialog-scoped snapshot before collection. |
| `renderer-route-read: CDP command timed out: Runtime.evaluate` after the submitted main marker is visible | Main-surface recovery performed a redundant `location.href` evaluation after exact marker verification; the busy Codex renderer can reject that read even though the validated main target and dialog are usable. | Keep the submitted job sealed; do not resend. | Reuse the discovery-validated main target URL for the recovery record and proceed directly to the dialog-scoped collection snapshot once the marker is visible. |
| `CDP websocket closed` during submitted main-surface read-only collection while the generated image remains visible | The retained main renderer can drop a recovery CDP connection after marker acknowledgement even though the ChatGPT dialog and rendered blob image remain present. | Keep the job sealed; do not resend or create another conversation. | Reopen one exact verified main-target CDP session, re-verify the exact marker, and continue collection once; if the second read-only connection fails, remain sealed and report the exact error. |
| Successful read-only resume leaves the matching ledger entry at `timeout-after-submit` | The resume path wrote its report and artifact but did not merge recovered status back into the generation lifecycle ledger. | Do not alter or delete the conversation; keep the artifact and ledger entry auditable. | Allow resume manifests to carry `jobType`, `retentionDays`, and `lifecycleLedgerPath`; after a successful resume, call the same atomic lifecycle merge used by batch dispatch. |
| `runId must be non-empty text` while merging a successful resume | Resume reports lacked their own run identifier even though lifecycle entries require one; the artifact collection itself had already remained read-only. | Keep the recovered job and existing conversation unchanged; do not resend. | Generate a fresh resume `runId` at report start and use it only for ledger provenance. |
| `discover` / `probe: fetch failed` with no listener on the standalone state port | `%LOCALAPPDATA%\CodexChatGPTBridge\state.json` references a Codex loopback endpoint that is no longer live. This is an unavailable bridge runtime, not evidence that a generation job is safe to send. | Stop before batch; do not guess a port and do not close or restart an existing Codex window without explicit authorization. | Verify `/json/version` and registered-package listener ownership. Refresh state only with `start-chatgpt-bridge.ps1`; use `-RestartExisting` only after authorization, then rerun discover and probe sequentially. |
| `discover: Registered OpenAI.Codex package was not found` after a Codex update | The standalone bridge state pinned an older package full name/version while the installed official package had advanced. Treating stale package identity as current blocks discovery even when a loopback listener exists. | Stop before batch; do not edit state by hand and do not guess a package version. | Re-run `start-chatgpt-bridge.ps1` to validate the registered Store package and atomically refresh generic bridge state. Update the version-pinned quick-chat RPC map only after inspecting the installed bundle's actual RPC asset and service export; rerun discover and probe sequentially. |
| Bare `Runtime.evaluate` during recovery | Failure site was not observable, causing speculative fixes. | Stop and add stage annotation before retrying. | Wrap renderer route, renderer-ready, composer, history list, row open and marker scan evaluations with exact stage labels. |
| Direct local route opens but original marker is absent | The local conversation route is not the persisted submitted history item. | Do not export content; enter marker-guarded history fallback. | Direct recovery must require the original marker before collection. |
| History fallback waits forever for a synthetic route | A blank prewarm window need not adopt the temporary recovery ID. | Keep the fallback read-only and continue only from a proven blank surface. | Generation/direct recovery require exact routes; history fallback requires blank composer plus zero conversation units, then visible titled rows plus original marker. |
| `watch` identity matches but returns zero units while the ChatGPT control surface is not mounted | The active thread identity can remain discoverable from Codex chrome even when the integrated ChatGPT conversation root is absent. Treating zero collected units as a readable empty conversation creates a false `no-handoff`. | Keep the operation read-only, return `conversation-not-readable`, execute nothing, and ask the user to activate the exact pinned ChatGPT control conversation before another bounded watch. | The DOM snapshot must return a separate `readable` sentinel for a visible ChatGPT dialog or confirmed active ChatGPT document. Identity equality alone is insufficient; zero units may become `no-handoff` only when `readable=true`. Regression: `handoff DOM collection is read-only and scoped to rendered conversation units` plus a live read-only smoke that returns `conversation-not-readable`. |
| A batch-created handoff test returns `complete`, then its main ChatGPT drawer retains only the user unit or unmounts before approval | `batch` is a one-shot dispatch/collection lifecycle, not a persistent control-conversation owner. The transient retained main surface can enter teardown after collection, so a separate process cannot safely assume the assistant proposal remains mounted. | Do not resend the proposal and do not approve whichever conversation is currently visible. Keep the exact surface active, start bounded `watch` after the proposal appears, then send the user-authorized approval while watch is already polling. | Keep `approve` narrow: exact conversation ID + marker + task ID + blank idle composer + schema-valid proposal, with `-AllowSend`. It may send only `CODEX_APPROVE <taskId>` and must report `unknown-after-submit` after any ambiguous click. For embedded no-title Quick chat, `watch-before-approve` is mandatory because post-process ID recovery is not reliable. Regression: approve argument, manifest, scoped composer and wrapper tests plus a live concurrent one-conversation handoff test. |
| Real ChatGPT assistant proposal is visible as `CODEX_HANDOFF`, a `json` code-block label and JSON text, but `watch` expects literal Markdown backticks | The renderer strips Markdown fence characters and may replace indentation spaces with non-breaking spaces. Parsing only `innerText` cannot recover the source fence and rejects a valid visible task block. | Keep the conversation and approval untouched; do not loosen parsing to arbitrary surrounding text. | Collect bounded `<code>` contents from assistant-role rendered units. Accept exactly one `CODEX_HANDOFF` and exactly one code block, normalize only display NBSP to spaces, then apply the unchanged strict JSON schema. Regression: `handoff accepts one rendered assistant JSON code block after Markdown fences are stripped`. |
| `watch` exits with `manifest is not defined` before reading an already-approved conversation | `readHandoffObservation` passed an out-of-scope variable into the identity-scoped DOM expression instead of its `expectedConversationId` parameter. The approval may already exist, but no checkpoint was written. | Do not approve again. Fix and test the read-only observation path, then rerun only `watch` while the exact conversation is still active. | Pass the function parameter directly and keep a source-level regression asserting that the observation helper contains no `manifest.*` reference. Regression: `handoff watch passes its expected conversation identity into DOM collection`. |
| 用户说“子代理”却被要求二选一，或被误路由成临时 worker；也可能把可见 `<codex_delegation>` 卡片当成发送 API | 术语已经固定：子代理是固定长期 Codex 对话/流程，应直接走 `codex-conversation`；子智能体才是临时并行 worker，走 `codex-subagent`。卡片和 `source_thread_id` 仍只是系统生成的追踪元数据，不是用户协议。 | 发送前直接选择 `codex-conversation` 并固定精确 `threadId`/`hostId`；不要投给最新或可见任务，不要手写、抓取或仿造 delegation 元数据。若用户同时提出冲突的临时与长期要求，才暂停澄清。 | 在 Skill、native contract、用户指南中维护固定术语映射；回归测试 `native-codex-bridge-skill-tests.mjs` 验证“子智能体→`codex-subagent`、子代理→`codex-conversation`”及不再要求二选一。 |

## Retry gate

Before any retry, answer all of these in the report or task notes:

1. Was the original job submitted?
2. Is the next operation send-capable or read-only?
3. What exact stage failed?
4. What changed since the previous attempt?
5. Which test proves the change?
6. Does the next attempt risk duplicate generation?

If any answer is unknown, fail closed. A user may explicitly authorize a different fresh job, but it must receive a new conversation, job ID, marker and lifecycle entry; the ambiguous original remains untouched.
