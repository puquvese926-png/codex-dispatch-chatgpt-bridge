# Codex Dispatch ChatGPT Bridge 产品介绍

## 一句话定位

`Codex Dispatch ChatGPT Bridge` 是一个把 Codex、ChatGPT、临时子智能体和长期子代理连接起来的协作调度 Skill。它负责路由、身份、授权、结果回收和失败恢复，让多模型协作从“窗口之间传话”变成可审计的任务流程。

## 用户痛点

复杂 AI 工作通常同时包含几种不同性质的工作：

- GPT 擅长创意、规划、文字分析和视觉提示词；
- Codex 擅长访问本地文件、运行命令、修改代码和执行测试；
- 临时并行任务适合快速审查和探索；
- 长期专项任务需要保留独立历史和稳定职责。

如果这些工作都依赖当前可见窗口，常见问题包括：目标串线、任务误投递、重复发送、提交状态不清楚，以及失败后不知道能否安全重试。

## 产品做什么

### 1. 统一四类协作路由

| 路由 | 角色 | 生命周期 | 结果去向 |
| --- | --- | --- | --- |
| `codex-subagent` | 子智能体 | 临时、有限范围 | 返回当前主任务 |
| `codex-conversation` | 子代理 | 固定、长期 | 保留独立对话和后续状态 |
| `codex-to-gpt` | GPT 工作节点 | 单次或批量任务 | 返回文本、图片、报告和哈希 |
| `gpt-to-codex` | 规划交接 | 提案—批准—执行 | 进入 Codex 正常执行流程 |

这里的中文术语是固定的：

- 子智能体 = 临时并行 worker；
- 子代理 = 固定长期 Codex 对话或执行流程。

### 2. 把 GPT 和 Codex 放进同一条工作流

```text
GPT：研究、规划、创意、提示词
          ↓ CODEX_HANDOFF
用户：确认任务和验收标准
          ↓
Codex：读文件、改代码、跑测试、整理产物
          ↓
GPT 或项目文档：复盘、继续规划、沉淀经验
```

### 3. 支持可追溯的生图协作

在生图场景中，桥接可以配合图片反向拆解、提示词设计和视觉验收流程：

```text
参考图
  ↓
提示词拆解与结构化
  ↓
Codex → GPT 独立生图任务
  ↓
图片、promptHash、参考图 SHA-256、会话身份
  ↓
Codex 验收、整理和归档
```

每个候选可以使用独立 GPT 会话，避免旧上下文污染；结果必须经过报告、产物哈希和生命周期记录后，才算可追溯。

### 4. 在发送前公布真实执行能力

ChatGPT UI 桥接不会把“理论可并行”包装成“当前一定可并行”。每个批次先生成
只读计划，公布当前模式、并发数和最坏等待时间：

- 生产默认：主 ChatGPT 串行模式；
- 实验模式：用户明确启用 Quick Chat 后，才尝试最多两个独立窗口；
- 已知故障：在同一 Codex 版本和浏览器会话中缓存，后续批次直接绕开；
- 多调用者：通过全局控制锁阻止同时抢占同一个主界面。

因此测试通过代表桥接代码满足合同；真实可用性还必须由当前客户端的只读
`discover`、`probe` 和 `plan` 结果确认。

## 典型使用场景

### 场景一：并行审查一个实现

主 Codex 派出三个子智能体，分别检查安全、测试和可维护性。它们完成后把结论返回主任务，主任务统一决定是否修改。

### 场景二：长期维护一个专项流程

把文档维护、发布准备或视觉规范交给子代理。子代理保留自己的历史，后续可以继续发送新的 brief，不需要每次从零建立上下文。

### 场景三：GPT 规划，Codex 执行

GPT 输出一个严格的 `CODEX_HANDOFF` 提案，用户确认同一个任务 ID 后，Codex 执行本地修改并返回测试证据。

### 场景四：参考图到生图产物

Codex 先整理参考图和提示词，桥接把自包含任务交给 GPT 生图，再由 Codex 验收尺寸、构图、风格和文件哈希。

## 产品价值

- 减少多窗口、多任务之间的串线；
- 明确“临时 worker”和“长期任务”的差异；
- 让 GPT 的创意能力与 Codex 的执行能力互补；
- 为每次发送和恢复保留身份和状态证据；
- 在失败时优先保护原任务，避免重复执行；
- 让复杂工作可以拆成可复用、可审查、可持续的流程。

## 安全边界

这个 Skill 不会把“看见窗口”当成“确认发送”，也不会默认发送给最新或当前可见任务。它要求明确授权、精确目标和必要的 marker；对 `unknown-after-submit` 和 `timeout-after-submit` 禁止自动重发。

它不读取 cookies、token、localStorage 或私有请求；不手写、抓取或仿造 `<codex_delegation>`；不把 ChatGPT 窗口伪装成 Codex 子智能体；也不是永久后台监听服务。

## 不负责什么

- 不替代具体项目的业务代码和运行时桥接实现；
- 不替代项目文档治理、素材管理或质量评审；
- 不自动替用户决定审美、产品方向或最终选图；
- 不在缺少身份、授权或可读性的情况下猜测并继续执行。

## 最适合的项目形态

它适合与项目文档系统、图片提示词 Skill、生图运行时和本地测试体系组合使用：桥接层负责可靠传输，项目 Skill 负责领域判断，Codex 负责执行和验证，文档系统负责长期沉淀。
